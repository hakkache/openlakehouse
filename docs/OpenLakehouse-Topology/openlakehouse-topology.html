Polaris is the seam

Spark writes and Trino reads the same tables because both resolve them through one Apache Polaris REST catalog. Take it out and you have two engines writing into the same bucket, blind to each other.

Storage is not the database

MinIO holds Parquet on your disk. Iceberg is the metadata that makes those files behave like tables — ACID commits, schema evolution, time travel — across bronze, silver and gold.

Two ways in

Debezium captures Postgres row changes into Kafka as they happen. Dagster runs scheduled Spark and dbt jobs. Both land in the same tables, so nothing downstream cares which arrived first.

Bring the profile flag back

docker compose down must use the same --profile you started with, or Compose silently leaves profile-gated containers running.
